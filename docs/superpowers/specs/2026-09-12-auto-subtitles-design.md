# Авто-субтитры: поиск, синхронизация, генерация, перевод

Дата: 2026-09-12
Статус: дизайн на ревью владельца
Репозитории: `web-ui` (выбор дорожек, гейт, UI, телеметрия), новые сервисы `subtitle-stt` и
`subtitle-translate`, `video-info` (поиск по imdb для сериалов, ранжирование), `rest-api`
(url_builder, Stremio), `infra/helmfile` (чарты, values, `torrent-http-proxy/services.yaml`)

## Проблема

Зритель запускает видео и не получает субтитров на своём языке. Замер за 7 дней (2026-09-11,
после включения бот-фильтра Umami):

| Метрика | Значение |
|---|---|
| Запусков видео / сессий | 10 009 / ~4 500 в неделю |
| Язык браузера не английский | 63% сессий (pt 20, es 11, fr 8, ru 6, zh 5) |
| OpenSubtitles по хэшу файла: пусто / ошибка / найдено | 84% / 7% / 9% из 21 049 запросов |
| OpenSubtitles по imdb-id: пусто | 2% из 370 запросов (1,7% всех запросов) |
| Ручных загрузок субтитров | ~35 сессий в неделю |
| Платных сессий с запуском | 158 (3,5%) |

Два вывода. Для большинства запусков внешних субтитров нет, но в основном из-за стратегии поиска:
хэш ломается на любом перекодированном файле, imdb-поиск находит почти всегда, однако не
гарантирует синхрон с конкретным файлом. И даже найденная дорожка чаще всего английская, а
зритель хочет свой язык. Значит, фича состоит из двух независимых частей: получить синхронную
дорожку-источник и перевести её.

Поиск не является каналом привлечения (DataForSEO 2026-09-12: `subtitle generator` 1 600/мес US,
`stremio subtitles` 4 400, `translate subtitles` ~1 300 на рынок, торрент+субтитры < 30). Канал
новой аудитории: Stremio-аддон и сообщества. Внутренняя ценность: удержание неанглоязычных
зрителей и конверсия в платный тир.

## Утверждённые решения

1. Лестница источников, сверху вниз: 0 загруженные пользователем, 1 встроенные в файл,
   2 приложенные в торренте, 3 OpenSubtitles по хэшу, 4 OpenSubtitles по imdb + автосинк по
   аудио, 5 whisper. Уровни 0–3 отдаются как есть, 4 требует синхронизации, 5 транскрипции.
2. Два прохода по лестнице для целевого языка: сначала «есть ли человеческая дорожка на целевом
   языке» (уровни 0–4), затем «есть ли источник для перевода» (0–5). Whisper и перевод это
   последний хвост, а не первый шаг.
3. Язык источника важнее его уровня: для перевода предпочитается дорожка на языке оригинальной
   аудиодорожки, затем английская, затем остальные. Whisper транскрибирует аудиодорожку на языке
   оригинала.
4. Реализация через torrent-http-proxy как два матрёшечных мода: `~stt` применяется к видео и
   отдаёт дорожку, `~tr:<lang>` применяется к любой субтитровой ссылке и отдаёт перевод. Никакой
   отдельной очереди, NATS-событий и таблиц задач: асинхронность через опрос, как у
   content-transcoder, кэш как у video-info.
5. Только платным тирам. Прогноз нагрузки ~25 задач в день, ёмкость не ограничение.
6. Модель whisper: large-v3-turbo q5_0 + Silero VAD, 8 потоков, потоковая нарезка по 30 с.
   Спайк 2026-09-12 на EPYC 7313P: 2,0× realtime на английском, 3,8× на испанском, отставание от
   просмотра равно длине куска плюс ~27 с.
7. Перевод существующих дорожек выкатывается первым и отдельно от whisper: он дешевле,
   быстрее и закрывает основную боль (63% не-en аудитории).
8. Fake door в плеере не критерий. Критерий: распределение закрытых запросов по уровням и
   использование дорожек после релиза перевода.

## Архитектура

### Цепочки URL

Всё строится на существующем парсере `~`-модов (`torrent-http-proxy/services/url_parser.go`),
включая синтаксис `~type:extra` и первый сегмент-мод (`/ext/`).

```
/<hash>/<path>/movie.mkv~stt/index.json            статус и список дорожек, запуск задачи
/<hash>/<path>/movie.mkv~stt/<aidx>.<lang>.vtt      транскрипция аудиодорожки aidx
/<hash>/<path>/movie.mkv~stt/<aidx>.<lang>.vtt~tr:pt/0.vtt   перевод транскрипции
/<hash>/<path>/movie.srt~vtt/movie.vtt~tr:pt/movie.vtt       перевод приложенного srt
/ext/<b64>/user.srt~vtt/user.vtt~tr:pt/user.vtt              перевод загруженного пользователем
/<hash>/<path>/movie.mkv~vi/opensubtitles/<id>.vtt~tr:pt/0.vtt   перевод дорожки OpenSubtitles
```

Уровень 4 (imdb + синк) живёт внутри `~stt`: `index.json?imdb-id=…&season=…&episode=…` заставляет
сервис сначала попробовать OpenSubtitles через `~vi`, синхронизировать и отдать как
`<aidx>.<lang>.vtt` с пометкой источника в `index.json`. Так web-ui не знает, синк это или whisper:
он видит дорожку и её происхождение.

### Сервис `subtitle-stt` (мод `stt`)

Go, urfave/cli, шаблон как у остальных. Exec `ffmpeg` и `whisper-cli` (whisper.cpp), `alass` для
синка. Читает `X-Source-Url`, `X-Info-Hash`, `X-Path`.

- **Ключ артефакта:** OSDB moviehash источника (64 KiB голова + хвост + размер, код из
  `video-info/services/hash.go`) + индекс аудиодорожки + язык + версия модели. Один файл в разных
  торрентах делит артефакт.
- **Распределение:** `NodeHash` + `preferLocalNode`, как у content-transcoder, чтобы читать аудио
  с сидера на той же ноде. Липкость по хэшу даёт дедупликацию одновременных запросов
  in-process семафором и пулом задач по образцу `RunManager`.
- **Протокол:** `index.json` возвращает `{status: pending|running|ready|failed, progress, source:
  human-sync|whisper, tracks:[…]}` и запускает задачу при первом вызове. `<aidx>.<lang>.vtt`
  отдаёт 202 с `Retry-After` пока пусто, частичный VTT с заголовком `X-Subtitle-Progress` пока идёт,
  200 с полным по завершении. Каждый HTTP-запрос короткий, таймауты ingress и Cloudflare не
  задеты.
- **Пайплайн whisper:** ffmpeg читает источник последовательно по HTTP, отдаёт 16 kHz mono PCM,
  нарезка по 30 с по границам VAD, `--prompt` из хвоста предыдущего куска. Пост-обработка:
  нарезка реплик 42 символа × 2 строки с минимальной длительностью, фильтр по no-speech
  probability, детектор зацикливания, дедупликация на стыках кусков.
- **Пайплайн синка:** кандидат из OpenSubtitles (через `~vi` с imdb, сезон, серия), ранжирование по
  похожести имени релиза, fps, флагу HI, числу скачиваний. `alass` по VAD-сегментам аудио. При
  низкой оценке совпадения дорожка не отдаётся, задача падает на whisper.
- **Хранение:** ход работы на hostPath-томе как у транскодера, готовый артефакт в S3 по ключу,
  ответы в lazymap и Redis как у video-info. Падение пода теряет только незавершённую задачу.
- **Ресурсы:** limit 8 CPU, 2 Gi на под, одна задача на под, worker-pool. Модель в образе.
- **Отказы:** источник без аудио, битмапные субтитры-кандидаты, неподдерживаемый язык, аудио
  короче 10 с: `failed` с причиной в `index.json`, web-ui показывает причину, а не пустой список.

### Сервис `subtitle-translate` (мод `tr`)

Go, urfave/cli. Читает `X-Source-Url` (субтитры в VTT), параметр языка из `~tr:<lang>`.

- Нормализует вход: вырезает HI-теги, склеивает разорванные реплики, присваивает id.
- Переводит батчами по 40–60 реплик с контекстом соседних батчей, сохраняя id и тайминги.
  Глоссарий имён из TMDB-каста (`ai_enrich`) передаётся через заголовок или параметр из web-ui.
- Модель: Claude Haiku 4.5, ~$0,15 на фильм. Провайдер за интерфейсом, в публичном коде только
  «upstream».
- Кэш: ключ = SHA-256 входного VTT + целевой язык + версия промпта. S3 + Redis + lazymap.
- Прогрессивность: если вход частичный (`X-Subtitle-Progress` < 100), переводит доступные
  батчи и отдаёт частичный VTT с тем же заголовком.
- Ограничение: вход больше 5 000 реплик или 1 МБ отклоняется, чтобы не переводить мусор.

### web-ui

- `handlers/action/helper.go` `GetSubtitles`: два прохода по лестнице для целевого языка (язык
  интерфейса, с возможностью выбрать другой в модалке). Фильтр встроенных: битмапные (PGS,
  VobSub) и forced (по disposition и числу реплик) не считаются найденными. Уровень 0 это
  существующие user_subtitle.
- Новые провайдеры `AutoSubtitle` (источник `~stt`) и `Translated` (любая дорожка через `~tr`),
  отдельная пометка «AI» в списке дорожек.
- Старт-эндпоинт `POST /auto-subtitle` за `claims.IsPaid` с квотой по тиру в стиле
  `handlers/discover_ai`; он же проверяет adult-классификацию и бан, отдаёт THP-URL. Дальше плеер
  опрашивает THP напрямую. Бесплатным показывается кнопка с замком и упсейлом.
- Плеер: дорожка через `AttachExternalFile`, перечитывание `<track>` по прогрессу, cue-offset для
  сессий с середины уже решён в `cue-offset.js`.
- Кнопка «не синхронно / плохой перевод» пишет событие с уровнем источника.
- imdb-id для `~vi` и `~stt` берётся из enrich (TMDB → imdb) и для сериалов дополняется
  сезоном и серией из имени файла. Сейчас imdb-id несут только 1,7% запросов; где он теряется по
  пути, выясняется в фазе 1.

### video-info

Поиск по imdb расширяется параметрами сезона и серии (`parent_imdb_id` + `season_number` +
`episode_number` в API OpenSubtitles). В ответ добавляются поля для ранжирования: имя релиза, fps,
HI, число скачиваний, флаг moviehash_match.

### rest-api

`url_builder`: две функции для `~stt` и `~tr`. Stremio: сгенерированные и переведённые дорожки в
поле `subtitles` объекта stream. Поле `lightExts` в values THP: `~stt/*.vtt` и `~tr` уже
попадают под `.vtt`.

### Телеметрия

Одно событие на закрытый запрос: `subtitle-resolved` с полями уровень источника (0–5,
none), язык источника, целевой язык, переведено или нет, тир. Событие выбора дорожки для всех
провайдеров, а не только загруженных вручную (сейчас `user-subtitle-select` единственное).
Дашборд по распределению уровней и доле whisper: это ответ на вопрос «нужна ли генерация».

### Гейтинг по возможностям

По правилу CLAUDE.md: поведение гейтится зависимостями. Мод `~tr` показывается, если настроен
провайдер перевода; `~stt`, если сервис объявлен в `services.yaml`; уровни 3–4, если задан
`OSDB_API_KEY`. Отсутствие возможности объясняется в интерфейсе, не скрывается молча.

## Риски

- **ToS OpenSubtitles.** Перевод их дорожки и раздача всем зрителям это производное. Условия API
  проверяются до того, как уровни 3–4 станут источником перевода. Whisper-дорожки риска не несут.
- **Качество whisper на современном кино.** Спайк на чистой речи старых фильмов; музыка под
  диалогом и наложенные реплики дадут хуже. Поэтому whisper последний уровень, дорожка помечена
  «AI», есть кнопка жалобы.
- **Полное чтение файла.** Синк и whisper читают файл через сидер целиком. Для зрителя, который
  смотрит, это та же закачка; для отложенного запроса это отдельная. Кап по размеру источника
  (например 12 ГБ) в MVP, 4K-ремуксы вне.
- **Контенция с транскодером.** Один под на ноду, limit 8 CPU, при 25 задачах в день незаметно.
  При росте нагрузки ограничение по числу одновременных задач на ноду.
- **Перевод с перевода.** Закрыт правилом выбора языка источника.

## Тестирование

- `subtitle-stt`: юнит на нарезку реплик, дедупликацию стыков, детектор зацикливания, парсинг
  сезона и серии; интеграционный на 10-минутном клипе с эталоном (WER не хуже спайка); негативный
  контроль на каждый фильтр (выключить и увидеть красный тест).
- `subtitle-translate`: юнит на сохранение id и таймингов, на HI-теги, на глоссарий; контракт на
  частичный вход.
- web-ui: тесты `GetSubtitles` на два прохода и фильтры (битмап, forced, язык источника),
  `make test`, а не `go test ./...`.
- THP: тест парсера на цепочку `~stt/…~tr:pt/…` (ожидается зелёный без правок).

## Фазы

| Фаза | Содержание | Оценка |
|---|---|---|
| 1 | Поиск: imdb-id из enrich во все запросы `~vi`, сезон и серия для сериалов, ранжирование; фильтр битмап и forced; событие `subtitle-resolved` и выбор дорожки для всех провайдеров | 3–4 дня |
| 2 | `subtitle-translate` + `~tr`, провайдер `Translated`, гейт и квота, UI с пометкой «AI», релиз платным. Первый публичный пост | 1,5–2 недели |
| 3 | `subtitle-stt` с whisper-пайплайном и прогрессивной выдачей, провайдер `AutoSubtitle` | 2–3 недели |
| 4 | Синк внутри `subtitle-stt` (уровень 4), ранжирование кандидатов, фолбэк на whisper по оценке | 1 неделя |
| 5 | Stremio: дорожки в `subtitles` объекта stream, пост в сообществах, замер установок и стримов | 3–4 дня |
| 6 | Опционально: ночной предрасчёт для популярных ресурсов по образцу `enrich popular` | 2–3 дня |

Между фазами 2 и 3 месяц сбора распределения уровней: если whisper требуется меньше чем в 5%
запросов, фаза 3 откладывается.

## Пороги успеха (8 недель после фазы 2)

- Доля запусков с выбранной дорожкой на языке зрителя растёт с текущих ~20% (2 168 srt2vtt на
  10k запусков, встроенные не измерены) до 40%.
- Конверсия в триал среди сессий, увидевших замок, не ниже средней по /donate (~8%).
- D30 когорты, использовавшей дорожки, не ниже базовых 6%.
- После фазы 5: установки Stremio-аддона и Stremio-стримы с нашими дорожками в сотнях в неделю.

## Вне объёма

OCR битмапных субтитров, перевод whisper-ом в английский (используется LLM-перевод), GPU,
бесплатный доступ, tool-страница «загрузи файл, получи SRT» (отдельное решение после замера).

## Открытые вопросы

1. Есть ли в THP-токене клейм, по которому сам прокси может отказать в моде `stt` и `tr`
   бесплатным, или URL защищается только тем, что web-ui его не выдаёт.
2. Условия API OpenSubtitles на перевод и кэширование производных.
3. Закрыто фазой 1: imdb-id приходил только из embed-настроек и API; теперь web-ui подмешивает его
   из enrichment вместе с сезоном и серией (для сериалов только при распознанных обоих, для
   многофильмовых паков только при совпадении пути). video-info ищет сначала по хэшу, потом по
   imdb, и держит два ключа кэша (по ноге поиска), чтобы `source` был фактом, а не выводом.
