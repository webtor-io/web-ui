# Onboarding via empty states

> Зонтичный документ по онбордингу — [onboarding.md](./onboarding.md): данные
> по активации, чеклист на главной, метрики. Здесь — только пустые состояния.

Пустые состояния (Library / Vault) — один из носителей онбординга, наряду с
чеклистом на главной. Причина выбора — они не требуют инфраструктуры: таргетинг
бесплатный
(экран видит ровно тот, у кого фича не активирована), состояние исчезает само
после активации, не нужна таблица прогресса, dismiss-логика и GDPR-экспорт.

## Что и где

| Экран | Файл | Что показывает |
|---|---|---|
| Library пустая | `templates/views/library/index.html` | «Browse torrents» + **«Watch on TV via Stremio»** → `/profile#stremio` |
| Vault пустой | `templates/views/vault/index.html` | «Open a torrent» → `/` |

Ключи: `library.watchOnTv`, `library.watchOnTvHint`, `vault.dashboard.emptyCTA`
— во всех 11 локалях.

Umami-события: `library-empty-connect-stremio`, `vault-empty-open-torrent`.

## Почему Discover сюда не входит

У Discover **нет пустого состояния для нового пользователя**: Cinemeta
(`CINEMETA_BASE` в `lib/discover/client.js`) подключена всем и всегда, поэтому
каталог непустой с первого захода.

Более того, компонент `NoAddons` в `EmptyStates.jsx` — мёртвый код: фаза
`no-addons` объявлена в типе (`discoverReducer.js:145`), но **не присваивается
нигде**. Единственная достижимая пустая ветка — `no-catalogs`, и она
выставляется при `types.length === 0` (`DiscoverApp.jsx:138`), то есть когда
манифесты не отдали ни одного типа — при живой Cinemeta это означает её
недоступность. Это состояние аварии, а не онбординга, и вешать туда
онбординговый CTA нельзя.

## Почему именно Stremio в приоритете

Замер ретеншна 2026-07-28 (прод-БД + Loki):

- Подключившие Stremio в первую неделю: **12.4%** активны спустя месяцы. Не подключившие: **1.4%**.
- Лифт ×9 сохраняется во всех стратах активности первой недели, включая тех, кто
  не сделал в web-ui вообще ничего (13.1% против 0.67%) — то есть это не селекция
  «активные делают всё».
- При этом Stremio отсутствует в навигации и на главной; единственный вход —
  блок в `/profile` (до этих правок — четвёртый по счёту).

Прочие фичи (WebDAV — 238 пользователей за всё время, embed-домены — 88) в
онбординг сознательно не выносятся.

## Терминология — важно не путать

Два разных объекта, оба исторически назывались «Stremio addons»:

- **Stremio-аддон webtor** (`access_token` со scope `stremio:read`) — подключение
  webtor **к** Stremio, воспроизведение на TV. Это то, что даёт ретеншн.
- **Источники каталога** (`stremio_addon_url`: Torrentio, MediaFusion, Comet) —
  сторонние аддоны, питающие **Discover** внутри web-ui.

Терминология пока не разведена нигде: блок `#addon-urls` в профиле называется
«Your Stremio Addons», тексты `discover.noAddonsTitle` / `discover.noAddonsDesc`
говорят «Stremio addons» про источники каталога. Переименование — отдельная
задача, см. ниже.

## Ограничения текущей реализации

- **Пустой Vault видит только платный тир.** Ветка `{{ else if .Data.IsFree }}`
  показывает free-пользователям upsell на донат, поэтому добавленная CTA
  достаётся лишь платным с пустым Vault — узкая аудитория.
- Ссылки с якорем `#stremio` идут **без** `data-async-target`: async-навигация
  подменяет `#main`, не обрабатывая фрагмент.
- Пустые состояния видит только тот, кто до них дошёл. Основная потеря воронки
  раньше: из регистраций до первого воспроизведения доходит ~19%.

## Блок Stremio в профиле

`templates/partials/profile/stremio.html` переработан:

- заголовок по ценности (`profile.stremio.title` + `profile.stremio.intro`)
  вместо технического «Addon URL»;
- расположение кнопок оставлено как было: строка `join` с URL и `Copy URL`,
  под ней `How to connect` слева и `Install in Stremio` справа;
- в ту же строку `join` добавлена кнопка-иконка ротации токена (круговая
  стрелка, `btn-square`), с `title`/`aria-label` из `profile.stremio.regenerate`;
- порядок секций в `templates/views/profile/get.html` пересобран: tier → vault →
  Stremio → Integrations (WebDAV, embed-домены) → Preferences (контент для
  взрослых). Раньше блок Stremio был четвёртым, после tier / vault /
  adult-настроек; теперь идёт сразу за vault, а Preferences ушли в самый низ.

Ротация деструктивна, поэтому submit формы обёрнут в
`onsubmit="return confirm(... | json)"` — тот же паттерн, что у удаления
embed-домена и аккаунта. Копирование в этой же форме — `type="button"`, чтобы
submit оставался только за ротацией. Без JS подтверждение пропускается; это
допустимая деградация, так как действие восстановимо (перевыпуск ссылки и
переустановка аддона), а не потеря данных.

`profile.stremio.addonUrl` больше не заголовок блока — ключ переиспользован как
`aria-label` поля с URL, у которого раньше не было метки.

Та же ротация добавлена в блок WebDAV (`profile.webdav.regenerate*`,
`POST /webdav/url/regenerate`) — общий код `models.RegenerateAccessToken`,
отличается только предупреждение: там речь о переподключении смонтированного
диска. Подробности в `docs/webdav.md`.

Шаг «Generate» **сохранён намеренно** — см. `docs/stremio.md`: это сигнал
намерения, и на `access_token` со scope `stremio:read` держится вся метрика
подключений. Автовыдача превратила бы её в «открыл профиль».

`handlers/profile/handler.go` теперь редиректит анонима на
`/login?return-url=<path>` вместо голого `/login`, иначе переход по CTA с
tool-страницы терял контекст. Фрагмент `#stremio` до сервера не доходит, поэтому
`/profile#stremio` не переживает логин. Решение: ссылки для возможно-анонимных
посетителей ведут на `GET /stremio/configure` — он прогоняет через логин и
приземляет на `/profile#stremio` (якорь едет в Location-заголовке). Так с
2026-09-01 работает `stremio_cta`.

## CTA на tool-странице

`templates/partials/stremio_cta.html` — по образцу `discover_cta`, ключи
`tool.stremioCta.*`, событие `stremio-cta-click`. Используется на новой странице
`/webtor-stremio-addon`. На `/stremio-addons-online` его ставить нельзя: та
страница обещает «Stremio без установки приложения». Подробности и данные —
[seo_stremio_pages.md](./seo_stremio_pages.md).

## Проверка

`go build` Go-шаблоны не парсит, а нужные ветки рендерятся только при
отсутствии данных, поэтому всё проверялось standalone-рендером по всем 11
локалям — парсинг, резолв каждого ключа, наличие/отсутствие строк в выводе:

- `library` (пустая), `vault` (платный пустой), `vault` (free upsell);
- `profile/stremio` в обеих ветках — без токена и с токеном;
- `stremio_cta`;
- `views/profile/get.html` — порядок блоков после перестановки.

Ротация токена проверена на реальной схеме в транзакции с `ROLLBACK`: два
подряд `generate` оставляют токен неизменным, `regenerate` его меняет, лишних
строк не появляется.
